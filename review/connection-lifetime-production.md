# Connection lifetime audit: production code

Scope: everything under Jube.* except Jube.Tests. Nothing was built or run. Only Rider lint was run on four of the
changed files, and it reported pre-existing style noise only.

## Root causes of the pool exhaustion evidence

1. The infrastructure samplers (`PostgresMetricSampler`, `PostgresLogSampler`) pinned one pooled connection each for the
   life of the sampler. `InfrastructureHealthMetricsStarter` never disposed any sampler on cancellation, so every engine
   host that was cancelled left its pinned connections behind (20 hosts, 20 pinned connections each).
2. `CachePayloadRepository.CreateAsync` constructed the repository without the cancellation token, so its 1-minute
   `Timer` was never disposed. Every host ever created kept running `ExecuteTimerWorkAsync` (the `LocalCacheInstance`
   writes) against Postgres after it was "stopped".
3. `FillPreferReplicaAsync` never disposed its `DbContext`. This was a real leak held for the duration of the fill.
4. `CacheService` had no disposal at all (ConnectionMultiplexer, sentinel multiplexer, payload timer).
5. `InfrastructureHealthMetricsStarter` never disposed `RespMetricSampler` (a multiplexer), `EtcdMetricSampler`,
   `PatroniMetricSampler` or the Docker proxy `HttpClient`.

## Long-lived background tasks (Engine host) and cancellation path

All are started through `TaskCoordinator.RunAsync` and exit on `TaskCoordinator.CancellationToken`: CaseCreation, Amqp,
NotificationsViaAmqp, WebhooksViaAmqp, Sanctions, GraphRecall, ExhaustiveTraining, AdvancedAnalyticsTraining, Tagging,
Counters, ApplicationLogEntry, InfrastructureHealthMetrics (now disposes samplers on exit),
InfrastructureHealthMetricsPurge, AsyncHttpContextCorrelation, CasesAutomation, CaseEscalation, CaseRisk,
CaseChecklistSlaSweep, WebhookRelay and NotificationRelay concurrent queues, EntityAnalysisModelManager,
HashCacheAssemblyObservability, CachePrune, LruJournalPrune, EntityReprocessing, EntityBacktest,
TtlCounterAdministration, AbstractionRuleCaching, ActivationWatcher, Archiver, ModelSync, the Cache pub/sub listeners,
and the Startup tasks (OtlpDispatchCounterFlush, ApiTokensCache, OpenTelemetryExcludeCache, LogCounterRuleCache,
InstantiateRepositories).

Tasks that had no effective stop path, now fixed: the `CachePayloadRepository` counters timer (token never passed), and
the AMQP teardown (cancelled token on `Task.Run`).

Resources the host does not own and the test host must still dispose: call `await cacheService.DisposeAsync()` in
`Jube.Tests/Infrastructure/ModelScaffolding/ModelEngineHost.cs` and the other test hosts. Today they dispose the
multiplexers only, so the payload timer survives unless the token is cancelled (it now is). I did not edit Jube.Tests.
