# Slice review: user-registry

Agent-mode review, 2026-11-08. Steps 0, 2, 3, 4, 5. Nothing was built and no DB-backed test was run (no infrastructure
assigned). One of three security-admin agents (user-registry, role-registry, tenant-registry); this agent is the sole
editor of `AdminSecurityPage.vue`.

## 1. Summary and verdict

Verdict: READY AFTER OWNER ACTIONS. The slice already carries very heavy coverage (110 service tests, 41 pen tests, 3
vitest specs, 21 e2e journeys). Secrets handling is sound: API keys are stored as hash plus 8 character prefix, shown
once, never listed, responses carry `no-store`, temporary passwords are Argon2 hashed, never logged, and neither
operation is an agent tool. Tenant isolation holds for read, update, delete, reset, revoke and key issue.

One real defect was found and fixed: renaming a user left the `UserInTenant` row under the old name, so the renamed user
resolved to no tenant (every service refuses with NotAuthenticated) and the old name stayed reserved. One test was added
for it (unrun). Two owner decisions are raised (privilege model, finding 3).

   `RenamingAUserMovesItsTenantMappingToTheNewNameAsync`) and `Category=PenTest` for `PenTestUserRegistry*`,

## 9. Manual test sheet

Built from the DTO, service, page and e2e spec.

1. Permission: user with 35 sees Users, Sign-ins, Sign-outs; without 35 none of those; with none of 34, 35, 36 the
   access-denied alert; 34 only shows Roles; no Role card link when lacking 34.
2. List: only own-tenant users; landlord sees own tenant only. Deep link `/administration/security` to a user and back
   button restores the record.
3. Create: empty name, 257 character name, duplicate name (also different case, also another tenant's user name, also
   the landlord's name), invalid and 257 character email, no role, role from another tenant (use dev tools). New user is
   inactive, switch defaults, locked with no password.
4. Update: change email, role, Active; concurrency in two tabs (second save conflicts); try editing Password locked
   (should be read-only); **rename a user, then reset the password and sign in as the new name** (the fix) and confirm
   the old name can be reused or is refused as intended.
5. Delete: user disappears; their API key stops working; their session is refused; name still unusable in another
   tenant.
6. Sign-in card: issue temporary password, copy, close, reopen (no password retained), check expiry text, sign in with
   it and be forced to change; Locked pill clears; response not cached (devtools). Revoke sessions: confirm text, user
   must sign in again, API key still works, `UserLogout` row shows the administrator.
7. API keys: Generate with empty name (refusal), 257 characters, description 1025 characters (input max length), reveal
   once, Copy, copy failure message, Done, reload shows only first 8 characters, Revoke asks first, revoked key stops
   authenticating, key for user of another tenant (devtools) is a no-op.
8. Own account (decision, finding 3): as a 35 holder change own role, deactivate self, reset own password.
9. Locales: en, pl, ar (RTL: secret inputs left-to-right, dialogs mirrored, chevrons), plus ka, id, sv, ur, hi once
   registered. Switch locale with the API key panel open and trigger the name refusal.
10. Responsive and theme: narrow width (no horizontal scroll), dark theme, keyboard only (dialogs trap focus, Escape
    closes), one hostile string per text field (`<script>`, `' OR 1=1 --`, RTL override character, 300 character emoji
    string).
