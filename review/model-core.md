Agent-mode review, 2026-11-08, steps 0, 2, 3, 4, 5. Nothing was built and no .NET or DB-backed test was run, Playwright
was not run. Vitest (src/story, 12 tests), prettier, eslint and `vue-tsc --build` were run on the files touched and are

## 1. Summary and verdict

Verdict: READY AFTER OWNER DECISIONS. The back end of the Model itself is well covered and no cross-tenant read, update
or delete hole was found for a model that has a tenant. Answers to the security questions in the brief:

1. **Tenant isolation (IDOR): closed for tenant-owned rows.** Every repository query filters `TenantRegistryId`
   (EntityAnalysisModelRepository.cs GetAsync, GetByIdAsync, UpdateAsync, DeleteVersionedAsync;
   EntityAnalysisModelRoleRepository.cs lines 48-80, 127). Covered by
   `EntityAnalysisModelServiceTests.UserInTenantBCannotGetUpdateOrDeleteTenantARowAsync` and
   `PenTestEntityAnalysisModel` via `ModelAreaPenTestBase.CrossTenant_ReadUpdateDeleteReset_BehaveLikeNotFoundAsync`.
   **Caveat (finding 1):** every one of those filters is `== tenant || !TenantRegistryId.HasValue`, so a row with a null
   tenant is visible and writable to all tenants. Left for the owner.
2. **Mass assignment: closed.** `EntityAnalysisModelMapper.ToPoco` copies only configuration fields; the repository
   stamps tenant, guid, created user and date, version, deleted markers (UpdateAsync lines 99-112). Covered by
   `TamperedIdentityAndAuditFieldsOnInsertHaveNoEffectAsync`, `TamperedIdentityAndAuditFieldsOnUpdateHaveNoEffectAsync`
   and `ModelAreaPenTestBase.MassAssignment_ServerOwnedFields_AreNotHonouredAsync`.
3. **Permission verbs.** Get-by-id, create, validate, update, delete, resubmit, retract all need permission 6; list,
   bounded list, filter fields, filter and count accept any of 6 to 26, 37, 3, 4, 1, 40 (read-only consumers such as the
   rule pages). Role allocation needs 6. Matrix covered by
   `EveryMethodThrowsForbiddenWhenPermissionMissingAndWritesNoRowAsync` and
   `AuthenticationAndAuthorisationMatrix_RefusesEveryone_ButThePermittedUserAsync`. No permissive grant path was
   introduced; no permission code was touched.
4. **Story page data sources.** `ModelStory.vue` reads the model list through `formModelApi.records` (the same
   tenant-scoped list endpoint), deep links carry only ids and are resolved against that list (settleDeepLink), child
   areas only from the model's own `children` (no link can name an arbitrary area), and every child read goes through
   its own endpoint's checks. Operate cards and synchronise are gated by permissions 40, 60, 5 in the UI and re-checked
   server side by their own services (model-integrity-sync owns those). No `v-html`, `innerHTML`, `href` or
   `window.open` anywhere in the slice's Vue files, so hostile model names render as text.
5. **Hostile names.** Server: `Injection_EveryTextField_IsStoredOrRejectedAsDataAsync`,
   `LengthBoundaries_AcceptTheMaximum_AndRefuseOneMoreAsync`,
   `TypeConfusionAndBoundaries_NeverProduceServerErrors_OrSideEffectsAsync` (PenTest base). Client: deep-link
   identifiers were parsed with `Number()` and accepted `0x10`, `1e3`, ` 7`; fixed to plain decimal (finding 3).
