# Slice review: graph

Agent-mode review, 2026-11-08 (interrupted once by a session restart and resumed, then a follow-up pass on owner policy:
leaks and gaps are fixed, not parked). Steps 0, 2, 3, 4, 5. Nothing was built and no .NET or DB-backed test was run.
Prettier, eslint and vitest (`src/graph`, 54 + 1 new test, all pass) ran on the Vue files touched; `vue-tsc` was not
run. Scratch files lived in `scratchpad/graph/`.

## 1. Summary and verdict

Verdict: READY AFTER THE OWNER MANUAL TEST, NO OPEN OWNER DECISION AND THE SERIAL TEST RUN. First pass: restricted-edge
leak in node facts, restricted edge evidence unreachable, unbounded traversal, unbounded expanded seeds, no query
timeout, pattern cased into an arbitrary case id, unbounded hub list, hard-coded English in SVG hover text, Vue bidi
gaps. Follow-up pass (owner policy: leaks are bugs): restricted edges no longer feed any cached analytics, case counts
follow the viewer's case workflow roles, a definition flipped to Restricted now restricts its existing edges at once,
stale analytics cleared, pattern job bounded. `vue-tsc --build` (npm run type-check) is clean.

Answers to the brief:

- **Tenant isolation.** Every node and edge query (`GetGraphNeighbourhoodQuery`, `Explode`, `Paths`, `Flow`,
  `GraphEdgeRepository`, `GraphNodeRepository`, `GraphPatternRepository`, `GraphCommunityRepository`,
  `GraphExplorationRepository` which also filters by user) filters `TenantRegistryId`. `GetGraphEdgeWindowQuery` has no
  tenant predicate but only receives edge ids already loaded through tenant-filtered queries. Joins are on `ArchiveKey`
  in the build only (`GetGraphBuildPairsQuery`, tenant via `EntityAnalysisModel`). All SQL is parameterised; no
  string-built SQL in any `GetGraph*Query`.
- **Caps.** Hops 3, fan-out 100, render cap 150, lanes 1000, transactions 5000, paths 6 hops / 20 results, flow rows
  2000. Gaps found and fixed: neighbourhood recursion enumerated paths with no row cap (fan-out 100, 3 hops is up to
  about 8 million rows), `Expanded` was unbounded, flow depth 6 with fan-out 50 was unbounded work, no command timeout
  anywhere in the read path, hub list loaded every hub before taking 500. There is no keyset paging on read endpoints
  (all are capped top-N lists); the build job pages by `ArchiveKey.Id` watermark (read, not changed).
- **Registry content.** Edge definitions hold report-key names (`FromKey`, `ToKey`, `FromNodeKey`, `ToNodeKey`,
  `AmountKey`), numbers and flags. No SQL, expression or path text is stored. Keys are length-validated only; they are
  used purely as bound parameters in the build join, so a hostile or unknown key yields no edges and no injection.
  Registry, edge and role writes check the parent registry and role against the tenant in validators and repositories
  (read: `GraphRegistryRepository`, `GraphRegistryEdgeRepository`, `GraphRegistryRoleRepository`,
  `GraphRegistryEdgeDtoValidator`, `GraphRegistryDtoValidator`, `GraphRegistryRoleDtoValidator`).
- **Viewer exposure, precisely.** Permission 49 or 1 (`PermissionValidation.Validate` is any-of) opens all reads; 51
  gates pattern decisions and hub overrides; 50 gates authoring. Any permitted tenant user can open any active registry
  by guid; role allocation only controls the directory list and Restricted edges. Restricted edges are now excluded
  everywhere for a non-granted viewer. Cached analytics (communities, patterns, hubs, node features) are built from
  unrestricted edges only (finding 6, fixed) and case counts on nodes require the viewer's workflow and status roles
  (finding 7, fixed). Case nodes are filtered per viewer (finding 18). Still exposed by design: the existence and name
  of a Restricted definition in the Neighbourhood definition list (shown greyed, asserted by an existing test).
- **Algorithms.** `SymmetricAdjacency` folds self-loops into `SelfLoops` used by `Louvain`; `Louvain` orders neighbour
  communities by key (`OrderBy`), and `DeterminismTests` exists. Edge list for algorithms is `LIMIT`-bounded. I did not
  re-derive the algorithms (see Not covered).
- **Viewer.** Layout is computed server-side by `Jube.Charting` on at most 150 nodes; the browser only pans and zooms an
  SVG, so there is no client layout cost. `GraphCanvas.vue` renders through `JubeChart` (sanitiser reviewed by
  data-grid, inherited). `Jube.Charting` `XmlText.Escape` strips bidi controls and escapes markup, and the chart CSS is
  `direction:ltr` (model-advanced-analytics fix). Labels are cut at 28 characters; the cut could split a surrogate pair
  (fixed). No remote asset is loaded by any graph file (grep for `http` found only licence headers). Export is the case
  Capture (SVG plus JSON, SHA-256 of the SVG).
- **`SelectToken`** and **`|| !TenantRegistryId.HasValue`**: none in any file this slice owns (grep over
  `Jube.Service/Query/Graph`, graph repositories, graph endpoints, `GraphJobs`, `GraphBuildQueue`).
